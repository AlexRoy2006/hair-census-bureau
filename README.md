# Hair Census Bureau

Build a premium, mobile-first web application called:

MUDI UNDO?™

Malayalam:

മുടി ഉണ്ടോ?

TAGLINE:

Official Human Hair Population Survey

PROJECT CONCEPT

This is a deliberately useless but technically impressive computer-vision project for a college competition.

The application asks a person:

“MUDI UNDO?”

“Do you have hair?”

The eventual application will use the user's phone camera to analyze their head and estimate hair density, scalp exposure, baldness index, and an approximate hair population.

For this first version, DO NOT implement actual computer vision, AI models, backend, authentication, or databases.

Build the complete polished frontend experience using realistic MOCK DATA.

The UI must feel so professional that the absurdity of the concept becomes funny.

--------------------------------------------------

VISUAL DIRECTION

--------------------------------------------------

Create a visual style that combines:

- Government census portal

- Scientific research dashboard

- Modern AI/computer-vision interface

- Official documentation

- Premium minimalist SaaS

The humor should be DEADPAN.

It should look like a serious government department has spent millions building software to count human hair.

Avoid:

- childish meme aesthetics

- cartoon-heavy design

- excessive emojis

- generic SaaS landing pages

- overly colorful gradients

- cheesy AI visuals

Use a restrained palette:

- Off-white / warm white background

- Near-black typography

- Dark forest green as the main accent

- Very subtle gray borders

- Occasional muted red for warnings

- Small amounts of pale green

Use strong typography hierarchy.

Use thin borders, technical labels, small metadata, grids, document-like sections, and precise spacing.

The design should feel like an expensive experimental government/scientific system.

TECHNICAL STRUCTURE

--------------------------------------------------

Keep the frontend modular.

Create reusable components for:

- Header

- Technical metadata

- Button

- Camera frame

- Scan visualization

- Statistic card

- Classification card

- Census certificate

- Dispute modal

Keep the mock analysis data in a separate data/config file so we can replace it later with actual computer-vision output.

Create a placeholder service/function such as:

It should currently return mock data.

Later we will replace this with a real browser-based computer-vision pipeline.
